# SeleniumBase behavioral compatibility matrix

Contract baseline: 2026-09-29, [issue #25][i25], parent [#24][i24]. BrowserDock reviewed: [`687d77e270cc49da02dacd312af5fc355aad9289`][bd]. SeleniumBase reference: **4.53.7**, commit **`4ee7dfc4ae83c19385f5ac129f2cda0cfa863d80`**. These are static source findings and implementation requirements, not new browser execution results.

This matrix defines the selected observable behavior for the independent .NET implementation. [spec.md](spec.md) defines Core invariants; [architecture.md](architecture.md) assigns responsibilities. Change all three together when scope or contracts change. Historical execution belongs in [implementation.md](implementation.md); future release support follows [support.md](support.md).

## 2. Shared contracts inherited by every row

The following rules plus each row's details specify preconditions, target policy, ordering, timing, completion, return state, cancellation, and reference lifetime. They are requirements for the planned surfaces, not a claim that pending fixes are already implemented.

### 2.1 Surfaces, state and ownership

- **Core** names below refer to existing `Browser`, `WebDriverLease`, `ElementRef`, and options. Core stays explicit and available. Its default startup and `NavigateAsync()` behavior do not change when UC is unused.
- **`UcSession`**, **`CdpPage`**, and **`NativeInput`** are planned API contract names, not currently callable types. `UcSession` is an opt-in facade borrowing one Core `Browser`; it does not own a second lifecycle. Modern methods return `ValueTask`/`ValueTask<T>`; Legacy exposes corresponding `Task`/`Task<T>` methods. Only `Browser.StopAsync()`/`DisposeAsync()` perform final browser cleanup. Python context-manager exit must never be mapped to .NET disposal/reconnect.
- `A` means healthy `WebDriverAttached`; `C` means healthy `CdpOnly`. Other states reject ordinary calls. Idempotent calls still probe health. Startup alone accepts no existing instance. Disposed objects are terminal.
- Operations resolve an explicit `TargetKey`, or the already controlled target; never infer the last window from array order or a window-handle string. Ambiguity fails before mutation. Replacement creates and identifies the new target before closing only the old controlled target; unrelated tabs survive. A closed key is never recycled.
- Disconnect invalidates WebDriver leases/elements before draining and stopping the exact owned driver. Successful attachment creates a new process/client/session and increments generation. Chrome PID/creation identity, profile, and debugger endpoint stay unchanged. Final cleanup uses exact ownership, caller-profile locks and marker-checked temporary-profile deletion, within the existing independent cleanup cap (ten seconds).
- Read-only waits may retry observations within one deadline. Side-effecting navigation, click, typing or submission is never replayed after an uncertain remote result. No private Selenium API/reflection, exception suppression masquerading as success, or raw Selenium objects at the public boundary.

### 2.2 Timing and cancellation

- **`DisconnectedDuration`** is a nonnegative finite `TimeSpan`: the minimum delay from confirmed driver shutdown to the next attachment attempt, or to return for a stay-disconnected helper. Scheduler/cleanup overhead may lengthen it. Explicit reconnect defaults to **100 ms**. Open, open-with-tab and open-with-reconnect default to **2.4 s** ([pinned constant][sb-duration]); the first two inherit upstream's context-manager delay ([initialization][sb-context-delay], [exit][sb-context]), not the bare `reconnect()` default. Open-with-disconnect defaults to **8 ms**. Explicit zero is honored. Python string sentinels and truthiness-based replacement of zero are intentionally unsupported; use the separately named operation. Fixed incidental sleeps are not API promises.
- **`OperationTimeout`** is a positive finite overall budget, beginning at API entry and covering gate/command-queue waits, stage work, observation and the disconnected delay. Default from Core: reconnect budget for lifecycle calls, navigation budget for navigation, command budget for interactions/input. Internal retries do not reset it. Reject a duration greater than or equal to the budget before mutation. A delay is never interpreted as a timeout, nor is Core `ReconnectDelay` relabeled as `DisconnectedDuration`.
- UC navigation that reconnects initiates navigation **before** disconnecting, observes the disconnected duration, then attaches. An optional explicit completion milestone is awaited **after** reattachment, under the remaining budget; it cannot postpone attachment behind a slow/missing page-load event. The default for UC helpers is **navigation initiated**, not `Load`. Their planned `UcNavigationResult` reports target, state, generation/epoch, and initiation versus an actually observed milestone; it must not reuse `NavigationOutcome.Completed` for an unobserved load.
- Cancellation while queued issues no commands. Before the first mutation, leave state unchanged. After detachment starts, finish bounded attachment cleanup independently of caller cancellation, then report `C` if Chrome/CDP/target health permits, otherwise `Faulted`. Cancellation during the disconnected delay does not trigger attachment. During attachment, remove an incomplete attachment; never expose partial success. If attachment committed before cancellation was observed, report the actual healthy `A` state and new generation rather than claiming rollback.
- After navigation dispatch or tab replacement, errors/cancellation carry stage, actual state and `BrowserMayHaveAdvanced=true` where the browser may have changed. Do not undo or automatically repeat that navigation. Failure before dispatch reports false unless another browser mutation already occurred. Timeout and caller cancellation remain distinguishable. Failed initial startup returns no instance and rolls back all owned resources. Final disposal continues bounded cleanup despite cancellation.

### 2.3 Context and references

- **WD lifetime:** epoch + target + frame path + DOM identity. Disconnect immediately makes old references stale; same-session DOM replacement is a distinct stale-DOM condition. Explicit reacquisition yields a new reference. High-level locator operations may refind before dispatch, but do not revive an old wrapper implicitly or replay a dispatched action.
- Core `FindOptions.FramePath` remains explicit. Planned `UcSession.SwitchToFrameAsync()` maintains a scoped locator frame path; relative frame switches append, and `SwitchToDefaultContentAsync()` clears it. Finds in that facade use the captured path. Navigation, target switch and disconnect clear this facade context; reconnect starts in the top-level document. Independent facades do not share implicit frame state. Initial nested iframe scope is ordinary same-origin frames; cross-origin/OOPIF and shadow-root traversal require explicit later support and must fail without acting in a different context.
- **CDP lifetime:** target + document/execution-context generation + protocol identity. Full navigation, context loss, target closure and CDP transport recovery invalidate existing references; explicit reacquisition creates fresh objects. Same-document navigation preserves references only while their node/context remains valid. A WebDriver epoch change alone does not invalidate a CDP reference. Release protocol objects/subscriptions on invalidation and disposal.
- **Native lifetime:** no DOM reference. Revalidate the owned Chrome window and foreground/focus before each sequence and after waits; window loss/focus loss aborts input. No implicit WebDriver reconnect. Native, CDP-dispatched and JavaScript input are distinct operations.

## 7. Core/Legacy and execution evidence

| Surface | Baseline build targets | Required browser execution baseline |
|---|---|---|
| Core modern API | `net481;net8.0;net10.0` | Core net8.0/net10.0, Windows 11 x64, interactive headed Chrome |
| Legacy, C# 7.3 consumer API | `net481;net8.0;net10.0` | Actual Framework 4.8.1 plus net8.0/net10.0, same platform and selected contracts |
| NativeInput (planned) | Must provide compatible modern/Legacy entry points for the baseline; not yet built | Separate desktop/DPI/layout capability matrix under #33 |

New supported functionality must expose the same state, timing, cancellation, errors, target/context and reference rules in Core/Legacy. Legacy snapshots caller-owned mutable options before asynchronous work, uses ordinary options/results/enums and Task APIs, and requires no records/init/required/ValueTask/IAsyncDisposable at the C# 7.3 call site. It wraps shared orchestration, not a second state machine; library awaits do not capture the UI context. Use awaited final cleanup in `try/finally`, never synchronous UI-thread blocking. An unsupported surface must be explicit in its matrix row before release.

The runtime matrix is a baseline, not a perpetual promise: [support.md](support.md) governs future release TFMs and lifecycle reassessment. In particular, reassess .NET 8 after its recorded 2026-11-10 support date; removing a TFM requires notice, not an automatic deletion by this document. ## 8. Provenance and change discipline

This change independently describes observable behavior; it does not translate or incorporate upstream implementation source. For each future copied/adapted unit, record the original repository, path and exact commit, copyright holder, applicable license and notice files, destination path, modifications, and redistribution location in [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) (or a linked checked-in provenance record). Preserve required license/notice text with distributed material; a URL alone is not a replacement.

An independent behavioral implementation and a source translation must not be described interchangeably. Existing review of GPL C# code is behavioral research, not permission to copy/translate it or evidence of a legally defined clean-room process. SeleniumBase's pinned MIT source and Selenium dependency notices retain their respective attribution requirements if incorporated/redistributed. Browser binaries remain caller-supplied and unbundled. No new source incorporation or dependency license change occurs in #25.

Closure of #25 requires coherent scope in spec/architecture/this matrix, every selected row mapped to a pinned source plus executable test or explicit tracked gap, clear timing/disposal rules, Core/Legacy/platform limits, and provenance rules. It does **not** require prematurely marking pending #29–#35 implementations complete. Changes to a row's behavior must update its tests, deviations and evidence together.
